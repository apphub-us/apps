## 2. Adapter model — one draft, one parser path, one engine call

```
LC = { snapshot (LoadCalcInput 3.2.1), fieldErrors {path: {raw, code}},
       loadErrors {loadId: {'rating.value'|'quantity': {raw, code}}},
       result, fault {kind: input|restore|storage, message}, sourceFavId, evaluations }
```

* **Init = Reset** — `EC.loadCalcState.createEmptySnapshot()` (T-S-08:
  `purpose: "service"`, everything else unknown, no loads, no measurement).
* **Numbers** — every number control goes through
  `EC.loadCalcInput.parseNumberField`: blank → `null` + parser `MISSING_FIELD`;
  malformed → `null` + `NOT_FINITE` with the raw text retained (`fieldErrors`);
  counts (`periodMonths`, `periodDays`, `intervalMinutes`, quantity) parse as
  integers (unsafe integers → `OUT_OF_RANGE`, never rounded). A native
  `validity.badInput` (text the browser holds but cannot expose) is the declared
  `NOT_FINITE` transport with `raw: ""`, never an intentional blank. Load
  `rating.value` / `quantity` cannot be `null` in the locked schema, so a
  malformed entry there keeps the last accepted number in the snapshot AND a
  load-scoped parse error (`loads[i].rating.value`) that blocks evaluation; the
  UI shows the raw text and "last accepted value is not used".
* **Enums** — `parseEnumField` against `EC.loadCalcInput.ENUMS`; a tampered
  option is `UNKNOWN_ENUM` with the raw value (T-S-36); a blank select is `null`
  (the engine reports the missing field).
* **Topology** — explicit enum → `EC.loadCalcState.supplyFor(topology)`;
  `other` → `{topology:'other', nulls}`; no label parsing. Load-model options
  come from `EC.loadCalc.MODEL_TOPOLOGIES`; a stored model not applicable to a
  changed supply stays selected (the engine reports `MODEL_UNSUPPORTED`).
* **Per-conductor inputs** — revealed by the topology's ungrounded conductors
  (`1ph_2w_120` → L1; 2-wire 240 V and 3-wire 1-ph → L1, L2; 3-ph → L1..L3);
  the map always keeps `L1/L2/L3` keys, a hidden or blank one is `null`.
* **Declared booleans** — unknown / yes / no selects produce
  `{ value, provenance: { source, note: null } }` (sources: `utility_data` for
  annual data, `recording_report` for the 30-day answers,
  `designer_declaration` for model declarations and attestations).
* **Guide** — `guideAnswers` are stored; `lcGuideRecommendation` maps them
  (house/apartment feeder + state, building cooking, non-dwelling) to
  `guideRecommendation`; the method is set from it only while
  `selectionSource !== 'manual'` (then `selectionSource: 'guide'`). A manual
  choice is never overwritten; a "Use the guide suggestion" link exists.
  Occupancy changes go through `setOccupancy` (loads/answers kept, guide-selected
  method and recommendation cleared). Restore never runs the guide.
* **Update** — `lcUpdate()` builds `{snapshot (clone), parseErrors (sorted),
  profileId}` and calls `EC.loadCalc.evaluate` **exactly once** (the only call
  site), then renders. `LoadCalcEnvelopeError` / any throw → `fault.kind =
  'input'`, result discarded, "INPUT REJECTED" shown; no forged result.
* **New-load term** — `precalculated` fields + basis (`method`, factors,
  `establishedForThisComparison`, `calculatedBy`, note); covered loads are
  ticked per load; `coversSnapshot` is written **only** by the "Confirm term &
  covered set" button (`EC.loadCalcState.captureCoversSnapshot`, single call
  site). Edits, evaluates, renders, restores and page loads never recapture;
  staleness is the engine's `AGGREGATE_STALE` (rendered in the covered-set
  note and the problem list).
* **Loads** — added from a preset name → category (Other → `classification:
  'required'`), VA and quantity 1, status unknown; edited inline; removed with
  ✕ (also dropped from `covers`). Legacy-migrated loads show their source
  item; unresolved migration items are listed as "Needs attention"; retained
  inactive data (floor area, laundry / NYC A/C counts, unit count, house loads)
  is shown read-only as "not used by profile A".
* **Rendering** — only engine values: status banner text per status,
  problems (`code`, field label, `ruleRef` via `necLink`), demand lines
  (`formatNumber` at the engine's display precision), current, existing
  capacity (`adequate` / `inadequate` = raw comparison with the entered rating;
  `not_assessed` says so with the blocking code), presentation labels,
  requiredCapacity / rating notes from the result, references. `COMPLETE` text
  states it is not approval. The diagnostic `continuityOfNewLoadKnown` is not
  rendered. Every NEC reference is a `span.nec-link` calling `necLink('NEC
  <ref> as amended by NYCEC 2025 — Load Calc, …')`; no inline handlers.
* **Faults** are transient: any fault is cleared by the next user update or
  Reset; while shown, no result is rendered under it.

## 3. Storage format

`localStorage['sparky_favorites']` is the shared object `{ vd, amp, cf, ww, lc }`.

```
NEW (B2) lc record:    { name, id, vals: { lcv: 2, profileId: "A_measured_87_core",
                          snapshot: <LoadCalcInput 3.2.1>, fieldErrors: {path: {raw, code}},
                          loadErrors: {loadId: {sub: {raw, code}}}, sourceFavId: <legacy id | null> } }
LEGACY (pre-B2) record: { name, id, vals: { method, voltage, scope, sqFt, appliances, hvac, ev, … } }
```

* A record is legacy exactly when `vals` has no own `lcv` property.
* Restore of a `lcv: 2` record: `profileId` must match, `validateSnapshot` must
  be empty, `fieldErrors` / `loadErrors` must be `{raw: string, code: parseCode}`
  shapes; otherwise "RESTORE FAILED" with the reason, draft untouched.
  `lcv ≠ 2` → explicit "saved by a different Load Calc version". The result is
  always recomputed on restore (no cached verdict is stored).
* Legacy restore: `EC.loadCalcState.migrateLegacyRecord(vals)`; nothing is
  written back; `sourceFavId` (adapter-only) remembers the legacy id; the next
  Save appends a NEW record with `sourceFavId` and leaves the legacy record and
  its `vals` byte-identical. `LegacyRecordError` (`LEGACY_UNPARSEABLE_LIST` /
  `LEGACY_ITEM_UNREPRESENTABLE`) → "RESTORE FAILED" naming the preset and the
  code only (no record content), draft/list/store untouched.
* Save (`lcFavSave`, the LC Save button): reads the store first — unreadable
  JSON / non-object → "STORAGE ERROR", nothing written, the corrupt content is
  NOT replaced; `setItem` failure (quota) → explicit error, nothing written;
  cancelled prompt → nothing. Ids are `Date.now()` bumped on collision. Unknown
  keys, other calculators' records, `null` entries and extra properties are
  preserved as-is. Malformed raw form input is saved as the typed
  `fieldErrors` / `loadErrors` state and restored verbatim.

## 7. B2-r1 — bounded integration fixes for the independent B2 review (R-B2-01..06)

Scope: the adapter block and the Favorites LC branch in `mobile.html`, the B2
tests/harness and this overlay. The three core modules, all other `src/`,
the locked fixtures/checkers/contract and the three diagnostic exceptions are
unchanged. Every "before" below was reproduced on the unchanged B2 tree with
the reviewer's own suites (Node 23: 7/16; Chromium 16: 4/12 in native and in
isolated mode) before any edit.

### R-B2-01 — editable load-card controls
* Before: every input event rebuilt the whole load list inside the result
  render, so the active label / rating / quantity input was destroyed after
  the first character (typed `My new charger` → `M`, focus on BODY).
* Fix: cards are built once per structural change (add, remove, restore,
  reset, sync) and kept in a `Map` keyed by load id; ordinary edits refresh
  each card in place (`lcRefreshLoads`: invalid marker, hint texts, coverage
  line, leg-control visibility, checkbox state, connection/leg options when
  the topology changed). No input is recreated or re-valued during an edit;
  focus, text, caret and composition state are the browser's. Handlers resolve
  their load by id at event time, so a snapshot replacement (`captureCoversSnapshot`,
  `setOccupancy`, restore) never leaves a card writing into a stale object.
  Still one evaluate per input event; no forced focus, no deferred validation,
  no zoom/font tricks.

### R-B2-02 — Favorites wrapper contract and restorable Save
* Before: quantity `0` / `-1` reached the snapshot, the core rejected it
  (INPUT REJECTED) but Save still wrote the record and reported success;
  reopening it failed. A stored `loadErrors` / `fieldErrors` of the wrong
  type (`[]`, string, `null`, number) was normalized to `{}` on restore, so a
  saved INCOMPLETE state came back as COMPLETE / adequate.
* Fix: (a) the form transport carries the locked schema's structural bounds
  (`loads[].quantity`: integer ≥ 1; `loads[].rating.value` ≥ 0; counts: safe
  integers), so `0` / `-1` are typed `OUT_OF_RANGE` parse errors with the raw
  text retained and the last accepted number kept — the snapshot is always
  schema-valid and the typed error is saved and restored losslessly; (b) one
  validator, `lcFavValidatePayload`, checks the COMPLETE lcv-2 wrapper: exact
  key set, `profileId`, `validateSnapshot() === []`, `fieldErrors` a plain
  object map keyed by paths in `LC_FIELDS`, `loadErrors` a plain object map
  keyed by ids of loads present in the saved snapshot with sub-keys
  `rating.value` | `quantity`, every entry exactly `{raw: string, code:
  parseCode[, badInput: true]}`, `sourceFavId` null | number | string. Restore
  validates first and then replaces the draft atomically (into prototype-free
  dictionaries); a failure leaves the draft, the store and the other records
  untouched and shows RESTORE FAILED with the reason. (c) Save runs the same
  validator on the payload before prompting: a draft this build could not
  reopen is refused with the reason and nothing is written.

### R-B2-03 — present malformed LC collection
* Before: `if (!Array.isArray(all.lc)) all.lc = []` replaced a present
  `lc` object / string / number with `[new record]` and reported success.
* Fix: an ABSENT `lc` key is created; a PRESENT non-array `lc` (object,
  string, number, `null`) is never touched — STORAGE ERROR, no prompt, no
  write, the store string preserved. Other calculators' collections, unknown
  keys and root-JSON corruption handling are unchanged.

### R-B2-04 — ids and dictionary keys are data
* Before: `LC.loadErrors[load.id]` on a plain object; a load id `__proto__`
  wrote `quantity` onto `Object.prototype` and the payload serialized `{}`.
* Fix: `fieldErrors`, `loadErrors` and each per-load map are
  `Object.create(null)` dictionaries written with `defineProperty` and read
  with own-key checks (`lcPut` / `lcGet` / `lcDrop` / `lcKeys`); restore
  copies own keys only; the card registry is a `Map`. `__proto__`,
  `constructor`, `hasOwnProperty` ids are ordinary own entries that survive
  Save → reload → restore; `Object.prototype` is never modified. No id is
  blacklisted; the core is unchanged.

### R-B2-05 — optional blanks vs required blanks
* Before: every blank number produced a parser `MISSING_FIELD`, so clearing
  the optional existing rating (or a once-typed OCPD) turned a COMPLETE demand
  into INCOMPLETE_INPUT although the core computes demand independently and
  reports the capacity layer as not assessed.
* Fix: `LC_FIELDS` describes each number path — `required: true` (reading
  value, annual months, 30-day days/interval, term VA; blank = parser
  `MISSING_FIELD`) or `required: false` (existing service rating / feeder
  ampacity / OCPD, power factor, per-conductor readings; blank = plain
  `null`, no parse error — the core decides: demand COMPLETE with
  `existingCapacity.status: not_assessed` and a capacity-layer
  `MISSING_FIELD`, a missing required conductor or kW power factor reported
  by the engine). Malformed text is still a parse error; nothing substitutes
  `0`. Additionally only errors of fields that are part of the ACTIVE form
  transport are sent (`lcFieldActive`): an error recorded on a field the
  current selections hide (e.g. the term VA after switching the mode to
  `none`, the annual months under the 30-day basis) is retained in the draft
  and in the saved payload and transported again when the field returns, so a
  hidden entry never blocks the visible route.

### R-B2-06 — visible app-authored NEC references
* Before: 7 app-authored visible texts (section title, hints, method note,
  capacity subtitle, attestation labels, the "Total for the 220.87(2)
  comparison" line label) carried reference numbers outside a link.
* Fix: `lcRich(text)` segments app- or engine-authored strings into text
  nodes and `necLink` spans for every reference number (`220.87`,
  `220.87(2)`, `230.90`, `240.4`, `220.61`, …) with the exact Load Calc
  context (`NEC <ref>[ as amended by NYCEC 2025] — Load Calc, existing
  service or feeder capacity (220.87)`). It is applied to labels, hints,
  titles/subtitles, notes, status banners, method/guide notes, engine line
  labels and engine notes — and never to user-supplied text (load labels,
  notes, preset names, legacy item names, the fault message), which stays
  inert. No innerHTML; native `<option>` text is not linked by design.

## 8. B2-r1.1 — closure of R-B2R1-01 (repeated load ids)

* Before (B2-r1): a shape-valid lcv-2 record whose `snapshot.loads` repeated
  an id passed the wrapper validator; the restore replaced the draft, the
  id-keyed card `Map` could never reach `size === loads.length`, and
  `lcRefreshLoads` → `lcRenderLoads` → `lcRefreshLoads` recursed until
  `RangeError`, leaving the previous COMPLETE / adequate on screen with a
  partially replaced draft (the accepted core alone returns `INVALID_INPUT /
  DUPLICATE_ID` for the same snapshot).
* Fix (adapter only): (1) `lcFavValidatePayload` rejects repeated
  `loads[].id` (`snapshot.loads: id "<id>" is repeated (positions i, j)`)
  — the same validator runs before a Save prompt/write and before a restore
  replaces the draft, so a failure leaves the active snapshot, `fieldErrors`,
  `loadErrors`, the stored record and every other collection untouched and
  shows RESTORE FAILED / STORAGE ERROR with no result rendered beneath.
  Only ids are compared: equal display labels and unique special-key strings
  (`__proto__`, `constructor`, …) remain ordinary data. (2) Render/refresh is
  finite by construction: `lcRenderLoads` records the structural signature of
  the list (ids in order, `LC.cardsKey`) before building anything, and
  `lcRefreshLoads` requests a rebuild exactly when the current signature
  differs, so the rebuild it triggers cannot ask for another. A draft whose
  loads repeat an id (reachable only through internal corruption) renders a
  read-only structural view naming the repeated id and positions
  (`LC.cardsInvalid`), the core reports `DUPLICATE_ID`, no old total is shown,
  and nothing is renamed, merged or removed; Reset or another preset leaves
  the state. The fault-rendering path uses the same finite refresh.
* Tests: `test/loadCalcB2r11.test.js` (6 explicit cases incl. positive
  controls), `test/loadCalcB2r1DuplicateIds.test.js` (the reviewer's 8 tests,
  ROOT line only), harness section F (native file:// storage, **real reload**
  before the row click, unique control, in-place typing in a restored card,
  internal duplicate → finite view → Save refused before the prompt → Reset).
