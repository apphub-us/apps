# LC-JOB-PHOTOS-1 — local original photos

## Flow and scope
Open a current saved Job card → Photos → Add photo. Select one local JPEG, PNG or still WebP and wait for its preview, then enter a title, optional multi-line location/notes, and an explicit stage: Not recorded / Before work / During work / After work. Save photo stores the original without compression, conversion or rewriting. Listing shows metadata without decoding a full gallery; Open photo reads and verifies one original on demand. No AI interpretation, automatic readings, uploads, external service, original download/export or cloud backup is included.

File input accepts the supported raster types only; the file signature and bounded dimensions are checked before native decoding. MIME mismatch, unsupported JPEG encoding, malformed containers, animated images, HEIC/HEIF, SVG, GIF and video are refused. A HEIC/HEIF user must export a JPEG/PNG copy outside this app. The app does not rename a HEIC to claim it is JPEG. The accepted original means the exact bytes supplied by the browser file picker, which may differ from a camera master if the operating system exported/converted it before selection.

Limits: 12 MiB per file, 16,000 pixels per side, 60 million pixels. The native decoder handles display orientation; no canvas recompression occurs. File name, MIME, byte length, SHA-256, oriented dimensions and file-modified time are recorded. Archive-added time and file-modified time are explicitly NOT claimed to be camera capture time. Original EXIF/GPS may remain embedded in the unchanged bytes; the app neither extracts nor removes it. There is no claim of anonymization, authentic capture date or evidence certification.

Edit photo details changes only title/location/stage/notes/retained state and requires a reason for a real change. Each update creates an immutable detail version referring to the same original descriptor. New image bytes require Add photo. No-op updates write nothing. Stale updates conflict before the no-op decision and retain the user's draft. View detail history is read-only. Excluded means retained, not deleted: the original remains viewable and still counts toward capacity. It is not a privacy deletion or space-recovery command. Duplicate names or bytes are never merged automatically.

## Persistence
Three new modules: jobPhoto (pure revision metadata), jobPhotoFile (bounded file inspection, native decode and cryptographic verification), jobPhotoStore (native IndexedDB). All earlier src modules and database schemas are unchanged.

New database empire_code_photos v1: assets keyed by photoId, with byJobId index; revisions keyed by revisionId, with byJobId and byPhotoId indexes. Assets hold kind/version/photoId/jobId/file descriptor and a native Blob. Revisions hold identity/parent/sequence, jobId and last-verified jobRevisionId, archive/save timestamps, producer, details, the same immutable file descriptor and changeReason. IDs use secure 128-bit random photo1_/prev1_ values. Collisions have a five-attempt limit and never overwrite records.

The original asset and initial metadata revision are added in one readwrite transaction. Updates insert only a metadata revision; no asset replacement, put, delete, clear or migration path exists. Successful results are returned only after transaction complete; request success followed by abort is a failure. Parent job verification uses the existing job reader before the photo write and is not an atomic transaction across databases. Photo writes do not create a job metadata revision or change measurements, materials, Favorites or saved calculations.

Within the coherent transaction the adapter audits bounded originals, total/indexed revision counts and per-job full chains. Missing originals, orphaned assets, wrong job ownership, altered original descriptors, missing parents, excess capacities and non-indexable rows return explicit errors, never successful truncated/empty archives or automatic repair. List/read validates metadata and native Blob size/type; original byte digest and header verification is performed when opening the original, not advertised for a metadata-only list.

Capacity: 100 originals/job and 500 globally; 200 MiB/job and 500 MiB total; 20 detail revisions/photo, 1000 revisions/job and 10000 globally. Excluded photos still count. These are implementation limits, not a guarantee that the browser has enough quota. Actual quota, blocked storage, unavailable crypto/decoder and newer/malformed schemas fail with retained existing data and an unsaved draft. Browser-local storage is not a backup and can be removed outside this app.

API: createPhotoStore(indexedDB,{crypto,decode,readJob,now?}) → create(jobId,fields,nativeFile), update(jobId,photoId,expectedRevisionId,fields,reason), list(jobId), read(jobId,photoId), original(jobId,photoId), close(). create captures metadata and the native File snapshot before async parent/database work. original returns the verified Blob and current detail snapshot; SHA-256 detects a difference from the stored descriptor, not authenticity against an external authority. Native decoding is injected through window.createImageBitmap in production; test doubles are explicitly distinguished.

## UI lifetime and noninterference
A pending photo draft blocks replacing the job, measurement or material editor until explicit Save/Discard. Older async navigation, decoding and original reads are ignored after generation/sequence changes. Invalid file replacement clears the selected file, not typed metadata. Refresh does not discard a draft. A stale detached Save cannot write. Native object URLs are released when changing/discarding a draft, closing/changing a photo view, starting another editor, moving to another job and on pagehide. Only one original/photo draft preview is displayed at a time. Closing/reloading the page can lose unsaved details/file selection; the editor warns about this.

User strings render as text, not HTML. New CSS is scoped to #lcContent; images fit the current viewport, labelled controls use at least 16px text and buttons at least 44px. Original image orientation/format decoding varies by browser; Safari, physical iPhone and installed/offline PWA require separate acceptance.

## Verification boundary
Pure model/file tests, simulated IDB with native Blob/File values, and shipped-adapter tests are separate from real-browser evidence. Native tests use local synthetic generated images and dedicated Chrome profiles, never the user's photo library or Safari profile. Fault injection is a deliberate native transaction abort, not a forced power-loss or actual disk-exhaustion proof. Historical tests are not silently marked passed from different test scripts.

Technical references checked for this implementation: IndexedDB transaction/Blob/commit/abort https://www.w3.org/TR/IndexedDB/ ; File API and object URL lifetime https://w3c.github.io/FileAPI/ ; native image orientation https://html.spec.whatwg.org/multipage/imagebitmap-and-animations.html ; WebP RIFF structure https://developers.google.com/speed/webp/docs/riff_container . Actual Empire Code behavior must be established by the checkpoint's executed logs.
