# Converter — Wh / Runtime (CONVERTER-WH-1)

A tab inside the existing Converter, next to Power: **"Na ile wystarczy bateria?"** — how long a power bank or
power station of a given capacity in **Wh** runs a load. Offline, deterministic, no storage, no network, no new
dependency. Power stays the default tab; the other converters are unchanged. mAh conversion is not included.

## Formula

```
availableWh = capacityWh × (chargePercent / 100) × (usablePercent / 100)
averageW    = W                          (mode "W — średnia moc")
            = kWh/day  × 1000 / 24       (mode "kWh/dobę — pomiar")
            = kWh/year × 1000 / 8760     (mode "kWh/rok — etykieta", 365 × 24 h)
hours       = availableWh / averageW
```

One source: `core/src/calc/batteryRuntime.js` (`EC.batteryRuntime` in the page). It parses the raw field text,
validates, calculates and produces every message and result string. The tab adapter (`bt*` functions in
`mobile.html`) only passes field values in and renders what comes back.

## Assumptions (all visible and editable in the tab)

| Input | Default | Valid | Note |
|---|---|---|---|
| Capacity (Wh) | blank | > 0, ≤ 10 000 000 | Energy, not output power in W. |
| Consumption | blank | > 0, average ≤ 1 000 000 W | Changing the unit **clears** the value; a number is never re-read in a new unit. |
| Charge (%) | 100 | 0 … 100 | 0 % is a valid result of 0 h. |
| Usable energy (%) | 85 | > 0 … 100 | An **editable estimate** allowing for losses — not a certified efficiency, not a universal constant. |

- The load is treated as a constant average. A measured kWh/day or a label kWh/year already contains a
  refrigerator's on/off cycling, so no duty cycle is assumed and losses are applied once.
- Watts measured while a compressor is running are **not** a daily average; for a cycling appliance use
  measured kWh/day or the energy-label kWh/year.
- Numbers accept a decimal comma or dot (`1,2` = `1.2`), whole value only: no exponent, no thousands
  separator, no trailing text. `1,000` therefore means 1; the result always echoes the interpreted inputs.
- Results over 100 years, or any non-finite value, are refused. A positive runtime under one minute is shown as
  "Mniej niż 1 min", never as 0 h. From 48 h the result is shown in days and hours.
- **Compatibility is out of scope.** The runtime assumes a suitable output. An ordinary AC refrigerator needs a
  suitable AC output with enough continuous **and** start-up surge power; Wh alone cannot confirm that it starts.

## Example (illustrative only — not the specification of any appliance, never a default)

"Przykład: lodówka": 1000 Wh, 365 kWh/year, 100 % charge, 85 % usable.
`365 × 1000 / 8760 = 41.67 W`; `1000 × 1.00 × 0.85 = 850 Wh`; `850 / 41.67 = 20.4 h` → **Około 20 h 24 min**.

## Build and test

```
# 1. inject the engine into both pages (same generated bytes; only the text between the EC-CALC markers changes)
cd core
node tools/build-calc.js                 # core/mobile.html
node tools/build-calc.js --workspace     # ../candidate/browser/workspace/mobile.html

# 2. core
node tools/build-calc.js --check && node tools/build-calc.js --workspace --check
node --test test/batteryRuntime.test.js  # module, parity, shipped tab
npm test                                 # whole core suite

# 3. app root
cd ..
npm run build                            # regenerates candidate/server/*.generated.mjs and the build manifest
node --test tests/converter-wh-runtime.test.cjs tests/browser-build.test.cjs
npm test && npm run build:check
```

`candidate/build.cjs` now lets `workspace/mobile.html` differ from its historical baseline pin (the pin itself is
unchanged evidence) and in exchange refuses the build if that file loses its host wiring: the host stylesheet
link, the `/sw.js` registration, or the three trailing host scripts. The other 14 assets stay byte-pinned.
